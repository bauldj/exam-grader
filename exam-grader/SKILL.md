# AI阅卷技能（exam-grader）

对纸质试卷扫描件执行"材料清点→批改→裁决→展示→交付"的**分步引导**阅卷流程。核心原则：**AI初判 + 人工校核，教师是最终裁决者；每步之间设检查点，经用户放行才进入下一步**。

## ⚠️ 开始前必读

**批改任何一步之前，必须先读取 [references/accuracy-rules.md](references/accuracy-rules.md)**。
该文件是多次真实批改实验沉淀的精度经验（7类典型失效、16条规则、答案优先比对策略、改判核算纪律），直接决定批改质量。跳过它会导致切边丢题、跨栏漏看、确认偏误判对、总分算错等已发生过的事故。

题位定位模板建立、多页扫描处理、评分细则（rubric）的详细操作见 [references/workflow-details.md](references/workflow-details.md)。
**50人以上大班阅卷，必须先读 [references/batch-mode.md](references/batch-mode.md)**（批量模式规范：模板复用、流水线批改、共性问题批量裁决、抽查与评语模板化）。

## 任务目录结构

在用户指定的工作空间创建：

```
<任务名>/
├── task.json          # 任务配置（科目、满分、题型分值结构、评分尺度）
├── roster.csv         # 学生名册（姓名、班级、学号）
├── blank/             # 空白卷（可选，用于精确定位）
├── template/          # 题位定位模板（redboxes.json / template.json）
├── answer/            # 答案库（answer_key.json，可含rubric）
├── scans/             # 学生扫描件（逐生逐页）
└── output/            # 成绩表、批改痕迹图、裁决记录
```

## 六步工作流（每步末尾有检查点，未经用户放行不得进入下一步；步骤6为自进化环节）

### 步骤1：材料清点（检查点1：材料齐备确认）

**触发**：用户上传附件或指定工作空间后，**立即停下来清点**以下四样材料：

| 材料 | 必须？ | 缺失时处理 |
|---|---|---|
| ① 学生试卷（扫描件/照片） | ✅ 必须 | 列出缺失，等用户补齐 |
| ② 答案（最好含评分标准/给分点） | ✅ 必须 | 说明"无答案则无法判分"，等用户补齐 |
| ③ 试卷答题区模板/定位依据 | ✅ 必须 | 无现成模板时说明"我将按空白卷或扫描件自动生成红框题位"，征得同意 |
| ④ 空白卷 | ⭕ 可选 | 说明"提供空白卷可显著提升定位精度"，无则按扫描件版式标定 |

**行为规则**：
- 逐项向用户报告"已有/缺失"，**缺什么指出来，等用户补齐后再动工，禁止抢跑**
- 材料齐后与用户确认：满分与题型分值结构（写入 task.json）、学生名册（roster.csv）、评分尺度（规则15，如"首行即错→全题0分"）
- 用户明确说"开始阅卷/材料齐了"才进入步骤2

### 步骤2：批量批改（检查点2：小问题攒批，重大歧义即停）

**触发**：用户放行后，开始逐生逐页批改。

- 批改顺序：逐题"先判是否作答 → 再判对错"（accuracy-rules.md 规则7）；有答案库时用**答案优先比对**（规则11）；判"对"前放大逐笔核验（规则12）
- **小问题（单题识别不清、字形存疑、字迹潦草等）**：不中断，记入 `output/疑难清单`（每项附裁图证据），继续往下批
- **重大歧义（全班性矛盾，如题干与官方答案冲突、评分标准缺失、扫描件与学生对应混乱）**：**立即停下来**向用户说明并等决定，再继续批
- 批改中按规则14逐题记分，**禁止增量式算总分**

### 步骤3：交互裁决（检查点3：用户逐项裁决，循环直至放行）

**触发**：全部试卷批完，向用户提交疑难清单，进入裁决循环。

1. 向用户展示：疑难清单（每项含：学生、题号、AI判读、证据裁图、候选答案、建议动作）
2. 用户逐项裁决 → 按裁决**逐题重算**总分并**全链路同步**（marks/小计/总分/评语/成绩表，规则14/16）
3. 重渲染受影响的批改图，验证落点（verify_marks.py）
4. **询问用户"还有要调整的吗？可以进入下一步吗？"——用户说可以，才进入步骤4；否则回到第1步继续裁决**

### 步骤4：成果展示（检查点4：用户确认成果）

**触发**：用户放行后，汇总展示两类成果：

1. **学生个人阅卷痕迹评分**：每生逐页批改痕迹图（`scripts/annotate_grading.py` 渲染：√/×/半对 + 大题小计 + 总分圈 + 红笔批语 + 可选行楷评语面板），逐生呈现
2. **班级总体得分统计表**：含平均分、最高/最低分、分数段分布、逐题得分率（选择/填空/解答正确率）——用对话内表格 + `output/成绩表.csv` 呈现

同时询问：**是否需要姓名脱敏**（必问项）。用户确认无问题后进入步骤5；有调整则回到步骤3。

### 步骤5：打包交付（检查点5：最终交付）

**触发**：用户确认成果无问题后，打包交付：

1. 将 output/ 下成绩表、疑难裁决记录、全部批改痕迹图打包为 `阅卷结果_<任务名>.zip`
2. 用 present_files 交付 zip，并附简明总结（定案成绩、关键失分点、留档事项）
3. 提醒用户：疑难裁决记录是研究素材，值得保留

### 步骤6：复盘迭代（检查点6：学习与自进化，用户批准后才写入）

**触发**：交付完成后主动询问用户："是否对本轮阅卷做复盘迭代？"用户同意才执行。

1. **自动生成本轮复盘报告**（`output/复盘报告.md`），内容：
   - 本轮新增的误判/修正类型与根因（从裁决记录中提炼）
   - 建议写入 references/accuracy-rules.md 的新规则草案（逐条列出，注明实证来源）
   - 评分尺度在本班的适应性观察（如某尺度引发多轮改判，提示复审）
   - 大班批量模式下可沉淀的流水线经验（如有）
2. **呈现报告并请用户逐条批准**——**未经用户明确批准，禁止修改本技能的任何文件**（人审闸门：一次偶发错误不能固化为规则）
3. 获批准的规则写入 accuracy-rules.md，**实证案例必须匿名化**（学生姓名→"某学生/学生A"，班级学号→泛化），写入后跑敏感词扫描确认零残留
4. 询问用户是否重新打包 .skill（用 skill-creator 的 package_skill.py 官方校验打包）
5. 记录版本变化：在对话中报告"技能 vX.X → vX.X+1，新增规则N条"

**自进化边界**：AI 负责提炼与提议，**用户负责批准与定版**——这是本技能与普通静态技能的根本区别，也是它越用越准的机制。

## 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/calibrate_grid.py` | 给扫描件叠加坐标网格，用于题位标定 |
| `scripts/verify_marks.py` | 程序化验证批改标记落点（红色像素聚类 vs 期望坐标） |
| `scripts/annotate_grading.py` | 渲染批改痕迹、脱敏、行楷评语面板 → 终版图 |
| `scripts/answer_key.py` | 答案库归一化比对判分（LaTeX↔普通写法） |

脚本均用 Python + Pillow（verify_marks 另需 numpy），无需联网。运行前先读脚本头部注释确认参数。

## 输出物清单（步骤5完成后交付）

- `阅卷结果_<任务名>.zip`（含以下全部产物）
- `成绩表.csv`（总分+细项+班级统计）+ 对话内汇总表格
- 每生 `批改_<姓名>_<页>.jpg`（含批改痕迹与评语）
- `疑难裁决记录.md`（每轮人机交互的判定与依据——可沉淀为实验数据）
